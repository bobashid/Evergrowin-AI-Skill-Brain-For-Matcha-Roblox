# Learned: unverified leads

Guesses and root causes without a test. They are never rules. Format: `UNVERIFIED (YYYY-MM-DD): <guess>. Test that would confirm it: <test>.` When one is proven, move it to the right file as Confirmed and delete it here.

- UNVERIFIED (2026-10-30): **`WorldToScreen(worldPos)` returns TWO values, `(Vector2, boolean)`** — screen position and an on-screen flag — and the Vector2 can be used directly as a Drawing `Position` / `From` / `To` with **no sign flip and no viewport offset**. Proof so far is a single third-party script (The Strongest Battlegrounds AutoBlock, Matcha Discord, June 2026) whose author reports it working: `local s_pos, on_screen = WorldToScreen(hrp.Position)` and `local sp, v = WorldToScreen(wpos)`. That is one sample from someone else's build, so it is a lead, not a fact. Test that would confirm it: one `matcha_exec` print of `WorldToScreen(<a part's Position>)` next to that part's known on-screen location, checking both the return order and whether Y needs flipping. Note the brain already carries the rule "`WorldToScreen` is only reliable inside a `RenderStepped` callback" — that constraint is separate from this signature question and is not in doubt.
- UNVERIFIED (2026-10-30): **The Strongest Battlegrounds exposes `workspace.Live` as the folder of live player models, and marks attack state with child markers `M1ing` / `NoBlock` on the model.** If those still exist, an autoblock needs no remote and no property writes: read the marker, hold the block key while it is present. The post is from June 2026 and the game has almost certainly changed. Test that would confirm it: list `workspace.Live` and print each child model's children while a player attacks. ## Older leads (Realistic Home Defense, ACS engine)

- UNVERIFIED (2026-10-26): **Realistic Home Defense probably locks its weapon settings, which would make every GC write inert.** The decompiled `ToolStorage.HK416.ACS_Settings` ends with `return require(game:GetService("ReplicatedStorage"):WaitForChild("ACS_Engine"):WaitForChild("Modules"):WaitForChild("LockSettings"))(v1)` - every gun's settings table is passed through a module named `LockSettings` before use. If that module freezes the table, copies it, or installs a metatable guard, then `applygc` writes to the pre-lock copy and can never affect firing. This would explain six versions of "doesn't work" better than any value-shape theory. Test that would confirm it: decompile `ACS_Engine.Modules.LockSettings` and see whether it calls `table.freeze`, `setmetatable` with `__newindex`, or builds a new table. Related probe that timed out (unconfirmed): whether `camRecoilUp` exists as its own GC key at all.
- UNVERIFIED (2026-10-26): writing `{0,0}` into the four inner `camRecoilUp/Tilt/Left/Right` pair slots removes the camera kick in Realistic Home Defense, because those slots already hold `{min,max}` tables so the write preserves shape. Test that would confirm it: scan, flip No Recoil, fire; the camera should stop climbing while the gun still fires normally. Status: the user reported v6.0 "doesnt work", so this is disproven or inert - see the LockSettings lead above before trying again.
- UNVERIFIED (2026-10-26): in Realistic Home Defense the ACS settings may be copied onto the equipped tool at equip time, so a GC write can land on a table the gun no longer reads. Test that would confirm it: flip No Recoil, re-equip the same gun, fire; if the kick only disappears after re-equip, the copy happens at equip time and the script should re-equip or write after equip.
- UNVERIFIED (2026-10-26): `applygc(cache, key, value)` accepts a filtered subset of the `getgc` result (only the entries a script kept), not just the full result. Test that would confirm it: a scan reporting `kept 2 of 35` followed by a write that returns a count above 0 and visibly changes the gun.

## Cross-game scripts do not transfer
A working GC stat script from another game is not evidence about this one. The Area51 example (`is_burst`, `shoot_wait`, `inaccuracy`, `fire_rate`, `is_auto`, `bullet_count`, `max_ammo`, `ammo`, `max_stored`, `stored_ammo`) targets lowercase scalar fields in plain readable tables. Realistic Home Defense runs the ACS engine with camelCase fields (`ShootRate`, `camRecoil`, `MinSpread`) and passes every settings table through `LockSettings`. Copying key names across games is guesswork; only the *shape* of the approach transfers.
