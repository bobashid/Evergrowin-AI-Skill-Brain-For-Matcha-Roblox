# Learned: corrections

When a line anywhere in the brain turns out to be wrong, fix it in place and record one line here: date, file, what changed, evidence. Never delete a rule without a replacement or a stated reason.

- 2026-10-30: **`workspace:Raycast` is a stub in this build: it accepts the call and always returns nil.** Six probes, including straight down at the ground from a standing character and a 20000-stud ray from the sky, all returned nil with `pcall` ok=true. `RaycastParams.new()` and `Enum.RaycastFilterType.Exclude` construct fine, so the constructor is real and the query it feeds is inert. `FindPartOnRay` and `FindPartOnRayWithIgnoreList` are nil, and `GetPartBoundsInBox` / `GetPartBoundsInRadius` / `GetPartsInPart` / `Region3` are all nil too, so there is no spatial-query fallback either. Rule: **never assume a raycast works because the function exists - probe a downward ray at the ground first.** Consequence: wall walking, ground detection and line-of-sight must be built from part geometry (`Position`, `Size`, `CFrame`), not queries. Evidence: `RaycastProbe` and `RaycastProbe2` in this session.
- 2026-10-30: **I claimed `workspace:Raycast` existed and built Wall Walk v2.0 on it without probing.** The API reference lists it under METHODS, so I treated that as proof. It is listed but inert. This is the second time this session a documented-but-unimplemented global produced a confident wrong answer (the first was `Humanoid.PlatformStand`). Rule: for any behaviour-critical global, the reference text is a hint and a probe is the proof. Evidence: v2.0 returned "no wall" while the user stood against a wall.
- 2026-10-30: **A write to a non-writable property inside a `pcall` is a silent no-op.** Wall Walk v1.0 wrapped `Humanoid.PlatformStand = true` in `pcall`; the property is not writable, the assignment raised `Unknown property`, the `pcall` swallowed it, and the script looked like it did nothing at all. Rule: never `pcall` a property write you have not confirmed is in the writable list - and when a script "does nothing", check for a swallowed error before redesigning the logic. Evidence: v1.0 behaviour, corrected against the Matcha API reference.

Rule already in `learned/working-style.md` - consolidate before a file stops being rewritable, and never shrink by discarding. Evidence: the pre-rewrite read-back.
