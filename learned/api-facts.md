# Learned: API facts and signatures

Proven by a probe, log or the docs. Format: `Confirmed (YYYY-MM-DD): <fact>. Proof: <source>.` When a fact corrects an `api-*` reference file, fix that line there too and note it in `learned/corrections.md`.

- Confirmed (2026-10-27): **`LocalPlayer.Character` reads `nil` in this build**, same family as `Player.CharacterAdded` reading nil. Consequence: `Players:GetPlayers()[i].Character == inst` never matches, so any "is this a player?" filter built on it silently fails and classifies players as NPCs. In CQB Hell the character model is named exactly like the player (`O_CsF`, `FakeAimbotON`), so filter on the player **name** instead. Proof: `matcha_exec` printing `CHK lpChar=true:nil`, plus a live probe that listed `O_CsF` and `FakeAimbotON` among the NPCs.
- Confirmed (2026-10-27): **`RunService.BindToRenderStep` and `RunService.UnbindFromRenderStep` are nil in Matcha** (`type(...) == "nil"` for both). Consequence: a script cannot choose its render priority. `RenderStepped:Connect` works, but the order of its callbacks relative to the game's own camera code is undefined, so a script cannot reliably run *after* the camera controller. Any camera-write technique that depends on winning the last write of the frame is therefore unreliable in this VM. Proof: matcha_exec printing `BindToRenderStep nil`, `UnbindFromRenderStep nil`.
- Confirmed (2026-10-27): ACS freezes every weapon settings table, so GC edits on them can never take effect. `ReplicatedStorage.ACS_Engine.Modules.LockSettings` decompiles to 15 lines: `if table.isfrozen(p1) then return p1 end; table.freeze(p1); for _, v2 in pairs(p1) do if type(v2) == "table" then recurse(v2) end end; return p1`. Every gun's `ACS_Settings` ends with `return require(...LockSettings)(v1)`. Proof: full decompile of `LockSettings`, Realistic Home Defense place 105527962898452.
- Confirmed (2026-10-27): writing to a frozen table raises `attempt to modify a readonly table value`. Probe: `table.freeze({a=1})` then `t.a = 2` returned `ok=false`, error `Matcha:4: attempt to modify a readonly table value 1`; `table.isfrozen` returned true. Proof: matcha_exec frozen-write probe.
- Confirmed (2026-10-27): `camRecoilUp` and `camRecoilLeft` exist as their own GC keys (5 and 14 entries) but **none of their values is a `{min,max}` pair table**, so a pair-shape filter keeps 0 entries and such a script writes nothing at all. Proof: `camRecoilUp: kept 0 of 5`, `camRecoilLeft: kept 0 of 14`.
- Confirmed (2026-10-26): **a `getgc` entry's `addr` identifies that entry's own value, NOT the table holding the key.** Measured: 35 `camRecoil` -> 35 unique addrs, 17 `ShootRate` -> 17 unique addrs, overlap **0**. Keys of the same table cannot be intersected by `addr`. Proof: `addrOverlap camRecoil/ShootRate 0`.
- Confirmed (2026-10-26): `getgc` cost is per key, about 6 s each. A periodic rescan is itself the lag; scan once on a button. Proof: timed probes.
- Confirmed (2026-10-26): `Player.CharacterAdded` reads **nil** in this build; `lp.CharacterAdded:Connect(fn)` dies with `Matcha:548: attempt to index nil with 'Connect'` and kills the rest of the chunk. Poll `lp.Character` instead - except that `lp.Character` itself also reads nil (see the 2026-10-27 entry above), so poll the workspace for the model named after the player.
- Confirmed (2026-10-26): **`require(<ModuleScript instance>)` fails in Matcha** - returns `false` plus a string error, never a table. Proof: `require ok false string`.
- Confirmed (2026-10-26): **a full `getscripts()` + decompile-everything sweep exceeds the 30 s tool timeout** and returns nothing. Find a script by name, or decompile one candidate. Proof: two timeouts this session.
- Confirmed (2026-10-26): `isrbxactive` is nil inside `matcha_exec` (the MCP sandbox), though real in a loader-pushed script. Proof: runtime hint plus `focus=err`.
- Confirmed (2026-10-26): a `matcha_exec` chunk is capped at **200 local variables** - `Matcha: error: too many local variables (limit is 200, got 205)`. Prefer table fields over many locals.
- Confirmed (2026-10-26): `getgc("laneAt")` returned 5 entries whose `value` is a **string**, so `getgc` cannot reach a game module's method by key name.
- Confirmed (2026-10-26): `RunService.PreRender` is nil in this build; `RenderStepped` and `Heartbeat` work. Use `RenderStepped`.
- Confirmed (2026-10-26): `keypress`, `keyrelease`, `mouse1press`/`mouse1release`/`mouse1click`, `mousemoveabs`, `firetouchinterest`, `fireclickdetector` all exist and return `ok=true` under `pcall` in a loader-pushed script.
- Confirmed (2026-10-26): a GuiObject's `AbsolutePosition` can be frozen at one value while idle and takes a full spread during animation. A never-changing value means "not animating", not "unreadable".
- User-stated (2026-10-26): `fireproximityprompt(prompt)` returns true on a `MountDinosaur` ProximityPrompt and completes the mount with no range check.
- User-stated (2026-10-26): `Humanoid.Sit` reads nil for a saddle mount; use a `CarriedDino` child or a seat/weld named seat, mount or saddle.
- User-stated (2026-10-26): `plot:GetAttribute('Owner')` returns the owning player's UserId as a number on Ride A Dino plots.
- User-stated (2026-10-26): `UI.GetValue(id)` and `UI.GetValue(name)` both answer; the id form is tried first.
- User-stated (2026-10-26): a `while running do ... task.wait() end` loop spins at about 60 kHz and starves the scheduler. Poll menus at `task.wait(0.15)`, action loops at `task.wait(0.25)`.
