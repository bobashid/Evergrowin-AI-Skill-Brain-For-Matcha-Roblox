# Learned: API facts and signatures

Proven by a probe, log or the docs. Format: `Confirmed (YYYY-MM-DD): <fact>. Proof: <source>.` When a fact corrects an `api-*` reference file, fix that line there too and note it in `learned/corrections.md`.

- Confirmed (2026-10-30, PROBED): **`workspace:Raycast` exists as a function but NEVER RETURNS A HIT in this build - it returns nil for every ray, everywhere.** Six independent casts all returned nil: 3 studs forward along the flattened look vector from the character; 50 studs forward; 50 studs straight down from the character standing on ground; 300 studs down; 900 studs down from 300 studs above; and a 20000-stud ray from (-5000, 5000, -5000). `pcall` returned ok=true every time, so the call is accepted and the answer is nil - a stub, not an error. `RaycastParams.new()` and `Enum.RaycastFilterType.Exclude` both work, so the constructor is real while the query it feeds is inert. Consequence: **nothing can detect a surface or obtain a normal in this VM.** Wall walking, ground detection, line-of-sight and any raycast-based ESP box are all off the table. Proof: `matcha_exec` probes `RaycastProbe` and `RaycastProbe2`, this session.
- Confirmed (2026-10-30, PROBED): **`workspace.FindPartOnRay` and `workspace.FindPartOnRayWithIgnoreList` are nil**; the `Ray` constructor itself is a table (exists). So there is no legacy raycast fallback either. Proof: same probe printed `FindPartOnRay=nil WithIgnoreList=nil Ray=table`.
- Confirmed (2026-10-30): **`Humanoid.PlatformStand` is NOT writable in Matcha.** The writable list is `Name, Parent, Position, Size, CFrame, Velocity, AssemblyLinearVelocity, CanCollide, FieldOfView, AbsolutePosition, AbsoluteSize, Value, WalkToPoint, WalkToPart` - PlatformStand is absent, so the assignment raises `Unknown property`. Inside a `pcall` that error is swallowed and the script appears to do nothing at all. Proof: the Matcha API reference read this session; Wall Walk v1.0 wrapped exactly that write and never changed behaviour.
- Confirmed (2026-10-30): **the only readable `Humanoid` properties are `Health`, `MaxHealth`, `WalkToPoint`, `WalkToPart`.** `WalkSpeed`, `JumpPower`, `Sit` and `PlatformStand` are neither readable nor writable as properties. WalkSpeed lives in the Luau heap: `getgc("WalkSpeed")` / `setgc("WalkSpeed", n)`. Proof: the API reference readable/writable lists.
- Confirmed (2026-10-30): **`Instance` does not exist at all - not merely `Instance.new`.** Nothing can be constructed: no Part, no ScreenGui, no Highlight, no BillboardGui. Every overlay goes through `Drawing`. Proof: the API reference, "DOES NOT EXIST - never call".
- Confirmed (2026-10-30): **assigning `Position`, `CFrame`, `Velocity` or `AssemblyLinearVelocity` performs thousands of internal memory writes per assignment.** A per-frame loop doing it "will destroy the game's framerate". Write them on a state change, or throttle to a few times a second - never once per `RenderStepped` unless continuous motion is the effect itself. Proof: the API reference PERFORMANCE section.
- Confirmed (2026-10-30): **`Players.PlayerAdded` and `PlayerRemoving` return nil** - those signals are never created, so poll `Players:GetPlayers()` and diff the list. **`IsA()` ignores its argument and always returns true** - compare `ClassName`. **`UserInputService.InputBegan` gives a table with only `.KeyCode`**, not a Roblox InputObject (no UserInputType, no Position, no gameProcessedEvent). Proof: the API reference.
- Confirmed (2026-10-30): **reading an unsupported property does not error - it falls back to `FindFirstChild` and returns nil.** Writing an unsupported property DOES error. So a nil read means "unsupported or absent", never "false". Proof: the API reference header.
- Confirmed (2026-10-26): isrbxactive is nil inside matcha_exec (the MCP sandbox), even though it is a real function in a script pushed through the loader. The runtime returned a hint saying so: hint: matcha_exec runs in a sandbox where isrbxactive is nil. Consequence: a probe can never prove whether input lands, because the focus check is unavailable there. Proof: matcha_exec printing focus=err plus the runtime hint, Piano Rhythm Tiles.
- Confirmed (2026-10-26): a matcha_exec chunk is capped at 200 local variables - Matcha: error: too many local variables (limit is 200, got 205). Wide probes silently die; prefer table fields over many locals. Proof: piano timing probe that errored, then the trimmed version that ran.
- Confirmed (2026-10-26): getgc("laneAt") returned 5 entries whose value is a string, not the module table, so getgc cannot reach a game module's press method by key name. Proof: matcha_exec printing vtype=string press=nil for every hit.
- Confirmed (2026-10-26): RunService.PreRender is nil in the current build (type(...) == "nil"), while RenderStepped and Heartbeat are tables and :Connect works. Use RenderStepped, not PreRender. Proof: matcha_exec printing pre=nil render=table hb=table in Piano Rhythm Tiles (place 101999883467300).
- Confirmed (2026-10-26): keypress, keyrelease, isrbxactive all exist as functions for a loader-pushed script, and mouse1press/mouse1release/mouse1click/mousemoveabs/firetouchinterest/fireclickdetector all exist and return ok=true under pcall. Proof: matcha_exec global sweep.
- Confirmed (2026-10-26): a GuiObject's AbsolutePosition can be frozen at one value while the board is idle (a tile read y = 364 and y = 1104 unchanged across many samples), but it takes a full spread of values during a live chart. A never-changing AbsolutePosition means "this element is not animating right now", not "the VM cannot read it". Proof: idle probes vs the live 8-tile snapshot (y from -194 to 1004).
- User-stated (2026-10-26): fireproximityprompt(prompt) returns true on a MountDinosaur ProximityPrompt and completes the mount with no range check. Proof: Ride A Dino dump, header "fireproximityprompt exists and returns true on that prompt", place 93523763376122.
- User-stated (2026-10-26): Humanoid.Sit reads nil for a saddle mount (no Seat or VehicleSeat exists). Use a CarriedDino child or a seat/weld named seat, mount or saddle instead. Proof: Ride A Dino dump.
- User-stated (2026-10-26): plot:GetAttribute('Owner') returns the owning player's UserId as a number on Ride A Dino plots under Workspace.Pens. Proof: Ride A Dino dump.
- User-stated (2026-10-26): UI.GetValue(id) and UI.GetValue(name) both answer in the build used by Ride A Dino; the id form is tried first. Proof: Ride A Dino toggle poller.
- User-stated (2026-10-26): a while running do ... task.wait() end loop spins at about 60 kHz on this build and starves the scheduler. The user's own scripts poll menu tabs at task.wait(0.15) and action loops at task.wait(0.25). Proof: Ride A Dino poller and mount loop.
