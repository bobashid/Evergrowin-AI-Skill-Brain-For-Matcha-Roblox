# Learned: error messages and what they mean

Format: `Error: "<exact text>" -> <meaning and fix>. Confirmed (YYYY-MM-DD). Proof: <source>.`

- Confirmed (2026-10-26): `Error: "Matcha:129: Expected identifier when parsing expression, got 'until'"` -> **a Lua reserved keyword was used as a bare table key.** `until` (and `end`, `for`, `do`, `then`, `else`, `in`, `not`, `and`, `or`, `local`, `function`, `repeat`, `while`, `if`, `return`, `break`, `nil`, `true`, `false`) cannot be written as `{ until = x }`. The whole chunk fails to compile, so **nothing runs at all** - not even the version print, which is why the failure looks like "the script did nothing". Fix: rename the field (`until` -> `due`) or use bracket syntax `{ ["until"] = x }`. Proof: Piano Rhythm Tiles v2.9 died at load with this exact error; v2.10 renamed the field to `due` and read back clean.
- Confirmed (2026-10-26): **a compile error means the file never ran, so a "does nothing" report after a push is not evidence about the game.** Check for a console parse error before re-reasoning about timing or lanes. Proof: v2.9's only symptom was this error; the behaviour it was meant to deliver was never exercised.
- Confirmed (2026-10-26): **two write results returning the same sha and size for two different paths** means the writes did not land as intended. Treat both as corrupt. Fix: re-read each path, compare the returned text against what was sent (spelling, duplicated sections, missing words), rewrite in full, read back again. Proof: a Ride A Dino brain push returned sha `f2a8c41d...` / 2,814 B for both `learned/patterns.md` and `learned/api-facts.md`; the read-back showed `CurriedDino` where `CarriedDino` was sent, one section duplicated, and words missing.
- Confirmed (2026-10-26): a read-back that returns only a heading, or returns another file's heading, is corruption or ordering trouble - not a successful read. Proof: same push as above, where the `api-facts.md` read returned `# Learned: patterns that worked`.
- Confirmed (2026-10-26): **a read-back can carry stray markup or duplicated lines.** Seen on `games/Piano Rhythm Tiles.md`: the text ended with a literal `</content></parameter>` block and repeated its final `Drawing` bullet twice. A write response reporting a fresh sha does not prove the stored body is clean - always read the tail. Proof: that read-back, this session.
- Confirmed (2026-10-26): a stale `sha` in `create_or_update_file` fails visibly (409 / mismatch), so it is safe to write with the last known sha and retry with a fresh read if it errors. Never silently overwrites. Proof: repo writes in this session that succeeded only after a re-read sha.
